# Справочник разработчика FoobarRemote

Внутреннее устройство приложения: архитектура, протокол MPD, поток запуска,
ключевые модули, паттерны состояния и типовые задачи. Конвенции оформления
кода вынесены в [AGENTS.md](AGENTS.md); здесь они не дублируются.

## Архитектура

Приложение построено без внешних стейт-менеджеров. Слои:

```text
Экраны (src/screens) и компоненты (src/components)
        │  useSyncExternalStore + вызовы действий
        ▼
Синглтоны состояния: libraryStore, playbackController
        │  вызовы функций
        ▼
Сервисы (src/services): MPD-клиент, настройки, импорт, обложки
        │  TCP-протокол MPD (react-native-tcp-socket)
        ▼
Сервер MPD / AsyncStorage / файловая система
```

Ключевые решения:

-   **MPD напрямую по TCP.** Приложение говорит на нативном протоколе MPD
    через `react-native-tcp-socket`. HTTP-слоя нет; каталог, очередь,
    обложки и состояние плеера читаются командами протокола.
-   **Два соединения.** Команды (`status`, `play`, `add`, …) выполняются
    на одном TCP-соединении (`mpdClient.ts`), события — на отдельном
    (`mpdIdleClient.ts`), потому что `idle` блокирует свой канал. При
    необходимости открывается TCP-соединение для проверки обложек.
-   **Синглтоны вместо React Context.** `libraryStore` и `playbackController`
    — экземпляры классов на уровне модулей: переживают смену экранов,
    не вызывают лишних ре-рендеров и тестируются изолированно.
-   **Подписка через версию.** Оба стора реализуют пару
    `subscribe(listener)` / `getSnapshot()`, где snapshot — счетчик
    `version`, увеличивающийся в `notify()`. Компоненты подключают его
    через `useSyncExternalStore`.
-   **События + тикер.** `playbackController` подписан на подсистемы
    `player`, `mixer`, `playlist`, `options` через idle и локальным тикером
    (раз в секунду) продвигает позицию между событиями. Подписка
    запускается по требованию `acquirePolling()` из `useFocusEffect`;
    счетчик потребителей гарантирует один idle-цикл на весь стек экранов.
-   **Ошибки как данные.** Сервисы бросают `LocalizedError` с кодом
    `err.*`; экраны форматируют их через `formatError(error, t)` на
    текущем языке, техническая причина добавляется в параметр `details`.

## Протокольный слой: src/services/mpd

| Файл                | Назначение                                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `mpdConnection.ts`  | Одно TCP-соединение: приветствие, `password` при наличии, посылка кадра команд, чтение ответа, таймауты                                       |
| `mpdClient.ts`      | Единственное командное соединение для всех сервисов: ленивое создание по настройкам, пересоздание после сбоя или смены host/port, `runMpdCommand` с обработкой ACK и закрытием при транспортных сбоях |
| `mpdIdleClient.ts`  | Отдельное idle-соединение: подписка на подсистемы, автоматическое переподключение с экспоненциальной задержкой (1–30 с)                       |
| `mpdParser.ts`      | Разбор строк `key: value` в пары, группировка в записи (`OBJECT_START_KEYS`), парсинг `status`, экранирование аргументов `quoteMpdArg`        |
| `mpdPlayerService.ts` | Снапшот из `status` + `currentsong`, команды play/pause/stop, `setvol`, `seekcur`; громкость 0..100, mute через `setvol 0`                  |
| `mpdPlaylistService.ts` | Управление очередью: `clear` + `add` порциями по 200 команд в кадре                                                                       |
| `mpdCatalogService.ts` | `listallinfo`: вся база MPD → `FoobarTrack[]`; лимит 200 000 треков; составные теги `3/12` разбираются в номер и количество                |
| `mpdArtworkService.ts` | Бинарные `albumart`/`readpicture` чанками по 8192 байта; таймаут 60 с; лимит 32 МБ; ACK = обложки нет                                       |

Детали протокола, о которых нужно помнить:

-   MPD 0.24 отдает бинарные ответы потоково, без завершающего `OK`,
    пока клиент не соберет объем из поля `size` — поэтому обложка
    запрашивается циклом с `offset`.
-   `runMpdCommand` возвращает `MpdAckError` как есть (это доменная
    ошибка сервера), а транспортные сбои закрывают соединение: следующая
    команда установит его заново.
-   Идентификатор трека — `${path}#${subsong_index}`; MPD всегда дает
    `subsong_index = 0`, поэтому один трек — один файл.

## Поток запуска

`App.tsx` загружает язык и монтирует `RootNavigator`, чей начальный маршрут —
`Start`.

```text
StartScreen (useFocusEffect)
    1. loadSettings()      → нет настроек?  → Settings(fromStart=true)
    2. validateSettings()  → ошибки?        → Settings(errors, fromStart=true)
    3. loadLibrary()       listallinfo → importLibrary → libraryStore,
                           восстановление CurrentPlayback
    4. loadCurrentAlbumToMpdPlaylist()
                           clear + add путей текущего альбома
    5. navigation.replace('Albums')
```

Любое исключение на шагах 3–5 уходит в `Settings` списком ошибок. Экран
`Settings` работает в двух режимах (см. `SettingsScreen.tsx`):

-   **fromStart** — форма не сохраняется сама; проверка и сохранение
    происходят при нажатии Back, затем `Settings` заменяет себя на `Start`
    (`navigation.replace('Start')`), и запуск повторяется;
-   **обычный** (открыт из NavigationBar) — измененные поля проверяются
    и сохраняются при выходе; библиотека здесь не перечитывается.

Если сохраненный источник воспроизведения больше недоступен (например,
плейлист удален на сервере), `StartScreen` сбрасывает состояние к первому
альбому: останавливает плеер, перезаливает альбом в очередь и сохраняет
новое состояние.

## Ключевые модули

### src/library

| Файл                 | Назначение                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `types.ts`           | Доменная модель: `Library`, жанр → исполнители/альбомы, альбом → диски → треки, `CurrentPlayback` (источник: альбом или плейлист)                                   |
| `LibraryImporter.ts` | Чистая функция `importLibrary(FoobarTrack[]): Library`: первое значение многозначных тегов, `album artist` → fallback `artist`, отсутствующий `genre` → `"?"`, диск → 1; ID альбома = `album artist\|album`; сортировка по disc, затем track |
| `LibraryStore.ts`    | Синглтон: хранит `Library`, выбор жанра/исполнителя, активный источник и `CurrentPlayback`. Селекторы возвращают новые массивы только при изменении данных          |

### src/services

| Файл                     | Назначение                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `settingsService.ts`     | Чтение/запись настроек в AsyncStorage с кэшем в памяти (idle-цикл и тикер читают их постоянно)                                                                |
| `settingsValidator.ts`   | Проверка настроек отдельным короткоживущим TCP-соединением с `ping`; результат `{ errors }`                                                                    |
| `fetchWithTimeout.ts`    | `fetch` с таймаутом (по умолчанию 5000 мс) — для HTTP-запросов вне MPD                                                                                         |
| `LibraryLoader.ts`       | Конвейер: `loadMpdLibraryTracks` → `importLibrary` → `libraryStore.setLibrary` → `initializeCurrentPlayback`                                                   |
| `playbackInitializer.ts` | Валидация и восстановление сохраненного `CurrentPlayback`, иначе первый альбом/трек (тот же порядок, что у списка альбомов: title → artist)                    |
| `playbackService.ts`     | Персистентность `CurrentPlayback` в AsyncStorage (`@foobar_remote/currentPlayback`)                                                                            |
| `playbackController.ts`  | Владелец idle-подписки и тикера, команды: playPause, selectTrack, selectAlbum, playPlaylistEntry, seek, громкость с preview/commit, mute; оптимистичная позиция после seek/play игнорирует сервер 2 секунды (допуск ±1 с); до первого ответа сервера громкость считается 40 |
| `playbackSyncService.ts` | `syncPlaybackSnapshot`: перенос активного индекса и позиции с сервера в `LibraryStore`, признак автопереключения трека                                         |
| `albumArtService.ts`     | Единая точка обложек: запрос по пути первого трека альбома, дисковый кэш `album-art-v3` в CachesDirectoryPath (имя `{artist}_{title}.jpg`), прогрев списка пулом из 4 загрузок, удаление устаревших каталогов `album-art`, `album-art-v2` |
| `tracklistService.ts`    | Экран плейлистов: `listplaylists`, исключение `default`/`default playlist` (без учета регистра) и пустых, `listplaylist` для количества, `listplaylistinfo` для метаданных строк |

## Паттерны для новых фич

### Добавить команду плеера

1. Добавьте функцию в `mpdPlayerService.ts`: собирает команду, выполняет
   через `runMpdCommand`, оборачивает транспортные ошибки в `LocalizedError`
   с кодом операции.
2. Добавьте метод в `PlaybackController`: выставьте `pending`, обновите
   оптимистичное состояние, вызовите сервис, обработайте откат при ошибке,
   завершите `notify()`.
3. Подключите метод к кнопке экрана; отдельная подписка не нужна,
   если экран уже читает состояние через `useSyncExternalStore`.

### Добавить экран

1. Создайте `src/screens/<Name>Screen.tsx` (default export).
2. Добавьте маршрут в `RootStackParamList` (`src/types/navigation.ts`).
3. Если экрану нужен пункт нижнего меню — расширьте union типа `active`
   в `NavigationBar.tsx`.
4. Экспортируйте экран из `src/screens/index.ts`, если он используется
   вне баррела.

### Добавить строку интерфейса

1. Добавьте ключ в `src/i18n/translations/en.ts` — он является источником
   типов `TranslationKey`/`TranslationParams`.
2. Добавьте перевод во все словари — `ru.ts`, `de.ts`, `fr.ts`, `es.ts`,
   `zh.ts` (тип `TranslationDictionary` не даст забыть ни один файл).
3. Используйте `t('ключ')` или, для параметров, `t('ключ', { name })`.

### Добавить ошибку сервиса

Код ошибки начинается с префикса домена: `err.catalog.*`, `err.playlist.*`,
`err.player.*` и т.д. Бросайте `new LocalizedError(code, params)`; ключ
обязательно добавляется во все файлы переводов. Транспортные ошибки
оборачивайте с параметром `details`, чтобы пользователь видел причину.

## i18n

-   `useTranslation()` подписан на смену языка через `useSyncExternalStore` —
    все экраны перерисовываются автоматически.
-   Язык загружается при старте в `App.tsx`; до загрузки действует
    `DEFAULT_LANGUAGE: 'en'`.
-   `formatError(error, t)` — форматирование `ErrorDescriptor`;
    `describeError(unknown)` — приведение пойманного исключения
    к дескриптору.

## Навигация

Стек `RootNavigator` содержит маршруты `Start`, `Main`, `Genres`,
`Artists`, `Albums`, `Playlist`, `Tracks`, `Settings`
(см. `src/types/navigation.ts`).

Правила переходов:

-   `Start → Albums` — только `replace()`: стартовый экран не должен
    оставаться в стеке; `Main` открывается тапом по мини-плееру;
-   `Start → Settings` — `navigate()` с `fromStart: true`, чтобы Back
    из настроек вернул управление запуску;
-   пункты NavigationBar используют `navigate()`, поэтому экраны библиотеки
    накапливаются в стеке, а выбор жанра/исполнителя живет в
    `LibraryStore`, а не в параметрах маршрута.

## Тема

Цвета — `src/theme/colors.ts`, типографика — `src/theme/typography.ts`.
Новые визуальные константы в компонентах не вводятся: сначала проверьте
тему. Стили colocated со своим компонентом через `StyleSheet.create`.

Режим темы (системная/светлая/темная) хранится в `themeService.ts` —
по тому же паттерну, что и i18nService: значение кэшируется в модуле,
сервис реализует `subscribe()/getThemeMode()/getResolvedTheme()` для
`useSyncExternalStore`. Компоненты читают палитру через `useTheme()`,
а для `StatusBar` используют `useResolvedTheme()` (светлая — темные
иконки, темная — светлые).

## Тестирование

Тесты лежат в `__tests__/` (`*.test.ts[x]`), пресет
`@react-native/jest-preset`, глобальные моки — `jest.setup.ts`.

```sh
npm test                         # весь набор
npx jest --runInBand             # последовательно — проще диагностировать RN-падения
npx jest __tests__/App.test.tsx -t "renders correctly"
```

Рендерные тесты пишутся на `react-test-renderer` с оберткой
`ReactTestRenderer.act(...)` — образец см. в существующих тестах.

Для тестов MPD-слоя подменяйте фабрику сокетов (`setMpdSocketFactory`
в `mpdClient.ts`, опция `socketFactory` у `MpdIdleClient`) — реальный
TCP в тестах не открывается. Для сервисов с AsyncStorage мокайте его
аналогично существующим тестам.

## Отладка

-   Все падения I/O логируются через `console.error` с контекстом —
    начинайте поиск с вывода Metro.
-   Транспортный сбой MPD-команды закрывает командное соединение и срывает
    поставленные на него команды; `mpdClient` логирует исходную ошибку
    через `console.warn` — ищите её, а не обезличенное
    «MPD connection is closed».
-   Если обложки не загружаются, проверьте таймаут `readpicture` (60 с):
    на больших файлах ответ занимает десятки секунд, и короткий таймаут
    срывает команды других воркеров.
-   Зависшее состояние Metro лечится `npx react-native start --reset-cache`
    (только для диагностики, не routinely).
